# S4 广告 · 可迭代首月方案

> 负责人：二十。 · 策略版本：s4-v1.0
> 输出遵循 contracts/交接内容.md；本阶段生成建议，不连接广告账户执行。

## 输入与边界

读取本轮 s3_listing.md（开发用 samples/s3_listing.md）的候选、Listing、关键词清单及来源，读取本轮 raw/ 的竞价缓存。S3 的 Highlights、长描述和后台关键词都属于合法来源。可选输入：用户确认的日预算与币种、产品事实。没有预算只写比例。

投放词只能取自 S3 **关键词清单**原词；大小写和多余空格可规范化，不扩词、不改单复数。S1、S2 或原始流量词中未进入 S3 清单的词不能直接投放。S3 的“有意没用的词”不是候选池。上游候选缺失或交接矛盾时记录问题并停止，不自行换品。S3 有规格占位或未通过检查时，标明“试跑草案、待确认”，不宣称可直接上线。

## 策略配置区（后续广告打法主要修改这里）

- strategy_version：s4-v1.0；每次改动递增，修改前先保存上一轮快照。
- 场景：美国站新品首月手动关键词方案；不含自动广告、ASIN 定向和真实广告复盘。
- 初始权重：精准 60 / 词组 30 / 广泛 10。仅是首轮假设，不代表行业最优配置。
- 筛词：先判断商品形态、材质、用途与购买意图。强相关保留；同类但宽泛且可控的词可小比例探索；歧义场景、形态冲突、依赖未确认功能、品牌/IP 词暂缓并逐条写原因。预算不足时优先核心意图。S3 放置位置只作上下文，不直接决定匹配方式。
- 匹配：清楚描述本品的核心/长尾意图优先精准；强相关的用途、属性组合可词组；强相关且有明确探索目的的词才广泛。允许同一词跨匹配方式，但必须说明测试目的；不为凑预算硬填广泛组。精准匹配也不保证实际搜索词逐字相同。
- 竞价：优先同站点、本轮缓存、相同原词的数据；记录工具、文件、统计周期及获取时间。使用工具 bid 作为市场参考起点，保留 bidMin/bidMax；不根据标题位置凭空加减。多个来源冲突时优先周期较新且口径明确者，记录选择依据。没有可靠 bid 时写“未查到”及原因；0/null/缺字段不当作免费流量。
- 补查：只对筛选保留且缺竞价的词批量 keyword_miner，参数 request.keywordList = 原词列表、marketplace = 本轮站点；通常最多 1 次，S4 新调用总上限 10 次。工具失败也计调用，禁止不断换词重试；查不到仍输出“未查到”。缺 bid 的词可以留在研究计划，但上线前需补全。
- 预算：空组分配 0%，其余组按初始权重 / 非空组权重之和归一化，保留两位小数，尾差加到非空组中权重最大的组，合计 100%。全部为空则停止，输出暂缓原因，不伪造 100% 预算。未提供总预算时不估美元金额。有用户日预算时据比例分配，金额尾差同样调整。
- 否定：只基于明确不相关购买意图制定“否定精准/否定词组”预案，每条写适用范围（精准、词组、广泛或全部）、原因与证据。证据不足写“暂无”。因利润不足而在 S2 放弃的候选特征，不直接变成否定词。否定词无需来自 S3；发布前检查同范围字面冲突与语义误伤。同词跨组迁移如需隔离，只在要排除的组内设否定，不全局误伤。这里是预案，真实搜索词报告未验证。
- 判断边界：searches/purchaseRate 是市场统计，不是本账户广告流量和广告 CVR；不得据此声称 ROAS、盈利或投放效果。未包含采购、头程、广告的 S2 利润空间不能充当可承受 ACOS。

## 执行顺序

1. **相关性筛选**：为 S3 每个词记录“保留/暂缓”、产品事实依据、歧义和待确认信息；暂缓词单列理由。
2. **缓存与竞价补查**：先查 raw/ 与调用账本；命中已有文件不重复请求。统计新调用和实际读取的不同缓存文件数（同阶段同文件只计一次），注明来源、周期、获取时间。保留返回原文，分页不完整也记录；不把缺失解释成没有市场。
3. **匹配方式**：按策略逐词给出匹配理由与探索风险；来源列指出 S3 中的位置及原来源。匹配组分别对应可隔离的活动/组，否定范围以这些组为单位。
4. **预算**：分配非空组，展示重分配算式。没有总预算时明确“未提供日预算”。
5. **否定预案**：写否词、否定方式、范围、理由；没有充分依据时为空。除脚本字面检查外，人工阅读词义与商品形态。
6. **输出与校验**：写本轮 s4_draft.json，运行命令。修复 S4 错误后再运行，不修改上游词来通过校验。--render 只有通过时写 s4_广告.md；失败写 s4_validation.json 并以非零状态退出。

```text
python stages/s4-广告/check_ads.py runs/<本次>/s4_draft.json --s3 runs/<本次>/s3_listing.md --render
```

校验器只做结构与交接检查，不内置 60/30/10、相关性阈值、匹配策略或否定选择策略。通过意味着结构可交接，不等于广告建议合理或效果已验证。S2 按规则停止时，不生成真实 S3/S4；S4 样例测试单独保留。

## draft 格式

完整虚构例子见 sample_draft.json；字段名是接口，策略值来自上面的配置。

- meta：seed、site、generated、data_period、upstream、candidate、strategy_version、sellersprite_calls（new/cache 非负整数）。
- ads：keyword、match（精准/词组/广泛）、bid（正数或“未查到”）、bid_min、bid_max（可选，正数或“未查到”）、bid_source、bid_period、reason、source。缺竞价必须填 missing_reason。
- deferred：keyword、reason；仅来自 S3，与 ads 不重叠。
- budgets：精准、词组、广泛各一行 {match, percent}；提供日预算时增加 amount。
- daily_budget：可选 {amount, currency}；未提供则 null。
- negatives：{keyword, match（否定精准/否定词组）, scopes（数组）, reason}，可以 []。
- notes：非空字符串数组，包含数据缺口、产品待确认、预算假设和上线前检查事项。

## 迭代与验收

同一轮保留 s3_listing.md、raw/、s4_draft.json、s4_广告.md、s4_validation.json、issues.md 和调用账本。issues.md 每项包含“异常现象、证据、所属阶段、建议修改、修改后结果”；未解决写“待验证”。

第一次结果完成后、任何修改之前，执行：

```text
python stages/s4-广告/review_iteration.py runs/<本次> --version v1
```

修改策略后优先使用同一份 S3 与原缓存生成新 draft、校验，再保存 --version v2 --previous v1。工具不覆盖已有快照，会对选词、匹配、预算、竞价、否词输出前后差异；输入或缓存变了会提示不能单独归因于策略。各次快照记录策略文件、输入、原始数据、输出、SHA256 与校验结果。只改上游输入/接口时重跑全链路。

验收分别记录：① 流程/字段/来源链是否通过；② 广告相关性、匹配、预算和否定预案人工评审结论；③ 真实投放效果“未验证”。保持本地，提交或合并由用户另行决定。
