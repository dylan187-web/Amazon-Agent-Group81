# PRD · S3 Listing 图片 v0.1

> Listing = 文案 + 图片。本文件管图片部分，文案部分见 `PRD.md`。
> 图片以 S3 文案产出（`s3_draft.json`）为输入，所以跑在文案之后。

## 1. 背景与问题

1. 卖家有了文案还要单独做 7 张图，外包慢、贵；直接用 AI 生图又常**篡改产品**：多画隔板、改结构、写错字，与实物不符会招来退货和差评。
2. 现成方案：
   - `amazon-image-generator` 是付费 API 外壳，不管保真；
   - `lc-amazon-image-studio` 保真设计最好，但依赖锁死版本的 Playwright / Chromium，本机跑不通，有云端鉴权，没有开源协议；
   - GitHub 上没有成熟的高星方案。
3. 我们的差异点：**图位由真实评论驱动，和文案一一对应**。买家在差评里最在乎什么，就给什么配图。

## 2. 目标与非目标

**目标**
- 一句话触发，给 S2 选中的候选出一套 7 张美国站 Listing 图：1 张主图 + 6 张副图。
- 每张图写明依据：来自哪个买家关心点、哪句文案。
- 产品保真：没有依据的细节不画；图上文字由代码排版，模型不写字。
- 规则由脚本检查：尺寸、主图白底、产品占比。

**非目标**
- 不做 A+、视频、多站点多语言。
- 不上传 Seller Central。
- P0 不做写实人物（避免 AI 写实人物披露要求），只允许不露脸的手部。
- 不照搬老陈 skill 的代码和文案（无开源协议），只借方法。

## 3. 输入

| 输入 | 来源 | 必需 |
|---|---|---|
| 文案、买家关心点、上架前待确认清单 | `runs/<本次>/s3_draft.json` | 必需 |
| 产品实拍图（多角度，白底更好） | `runs/<本次>/产品图/` | 可选；**没有就先生成 1 张「概念参考图」**，产出全部标「概念图，不可直接上架」 |
| 已确认的规格 | `产品信息.md` | 可选；尺寸图没有确认规格就挂起（HOLD） |
| 品牌名 / Logo | `产品信息.md` | 可选；没有就不放 |

## 4. 流程与功能

```
① 图位规划 → ② 参考图 → ③ Codex 出底图 → ④ 本地合成与排字 → ⑤ 质检（重做 1 次）→ ⑥ 渲染 s3_images.md
```

| 优先级 | 功能 | 说明 | 验收标准 |
|---|---|---|---|
| P0 | F1 图位规划 | 模型读 `s3_draft.json`，写 `images_plan.json`：7 个图位，每个含目的、画面描述、叠加文字（取自文案，≤8 词标题 + ≤3 条短句）、依据（关心点 / 文案位置）、出图方式、状态（ready / HOLD + 原因） | 每个图位有依据；需要未确认规格的图位为 HOLD，不编数字 |
| P0 | F2 参考图 | 有实拍图就登记角色（整件 / 局部 / 材质）；没有就调用 Codex 按文案生成 1 张白底概念参考图 | 概念图在文件名和产出里都有标注 |
| P0 | F3 Codex 出底图 | 脚本为每个 ready 图位编译提示词（开头写四项锁：结构、材质、场景尺度、关键细节），调用 `codex exec -i 参考图` 出**无文字**底图 | 底图存 `images/raw/`；调用失败重试 1 次，仍失败标 HOLD |
| P0 | F4 本地合成与排字 | Pillow：主图居中贴纯白 2000×2000 画布、近白像素归为 255；副图加标题条和卖点短句 | 字体、字号、对比度由代码控制 |
| P0 | F5 质检 | 脚本查尺寸、主图白底（边缘像素）、主图产品占比 ≥85%、文件大小；视觉检查（Claude 或 Codex 看图）逐图对照参考图，填结构 / 材质 / 多余部件 / 文字 / 合规 pass 或 fail | 不过重做 1 次，仍不过标 HOLD；没有质检结论不交付 |
| P0 | F6 产出 | 写 `s3_images.md`：图位表（图、目的、依据、叠加文字、质检结果）+ HOLD 清单 + 待补拍清单 | 与文案产出放在同一运行目录 |
| P1 | F7 实拍抠图 | 有实拍图时用 rembg / BiRefNet 抠图后合成主图（真实像素，不重画） | 需另装依赖 |
| P1 | F8 多候选批量 | 对多个 SKU 依次出套图 | — |

### 默认 7 个图位（按关心点排序，可替换）

| # | 图位 | 画什么 | 出图方式 |
|---|---|---|---|
| 1 | 主图 | 白底实物，无文字 | 合成（参考图 → 白底画布） |
| 2 | 头号关心点 | 回应最高频的差评（例：结构加固特写） | Codex 参考编辑 + 排字 |
| 3 | 第二关心点 | 例：放得下整套餐具，包括餐刀 | Codex 参考编辑 + 排字 |
| 4 | 差异化功能 | 对标没写的点（例：宽度锁定） | Codex 参考编辑 + 排字 |
| 5 | 尺寸 | 已确认规格的尺寸标注 | 代码画线标注；无确认规格则 HOLD |
| 6 | 使用场景 | 厨房场景图，允许手部，不露脸 | Codex 参考生成 + 排字 |
| 7 | 多用途 / 细节 | 书桌、浴室抽屉等，或防滑垫、清洁 | Codex 参考生成 + 排字 |

### 规则（脚本查）

| 规则 | 值 | 核实 |
|---|---|---|
| 尺寸 | 2000×2000 JPG，sRGB | 建议值；最长边 ≥1000px 才能缩放查看（第三方汇总） |
| 主图背景 | 纯白 RGB 255，边缘像素 ≥99% 为 255 | 第三方汇总一致，官方页正文未抓到 |
| 主图产品占比 | ≥85% | 同上 |
| 主图 | 无文字、Logo、水印、边框、额外道具 | 同上 |
| 写实 AI 人物 | P0 禁止；以后若加，XMP `dc:subject` 写 `contains-synthetic-performer`（exiftool 已装） | 卖家论坛公告 + 媒体报道，原文未逐字核实 |
| 叠加文字 | 只用文案里已有的说法；不写未确认数字；不写 best / #1 | 本项目自定 |

## 5. 约束与红线

- **时间**：官方提交截止北京时间周日 14:00。图片部分 12:45 冻结，13:00 全链路，13:15 录屏，13:45 前提交。
- **Codex 调用**：用本机 Codex CLI 自带的 `image_generation`（0.153.4，功能状态 stable，已开启）。额度走 Codex 账号，每次运行 ≤10 张（7 张 + 重做余量）；账号的生图额度上限**未核实**。
- **只有 Claude Code 的组员**：F3 需要本机装 Codex CLI；没有就停在 F1，输出图位规划。
- **仓库**：原图不入库；参考运行只提交 1000px 的预览 JPG（每张 <300KB），符合「不放大文件」。
- **SPEC 冲突**：SPEC 非目标写着「不做图片生成」，需要 Dylan 改为「图片属于 S3 Listing」。
- 不用竞品图片冒充自己的产品；不画竞品品牌 Logo。
