# PRD · S3 Listing Agent v0.3

> 本文件只管 S3 阶段。项目级约定以 `SPEC.md`、`contracts/交接内容.md` 为准；和它们冲突时以它们为准，需要改的在第 7 节列出，由 Dylan 拍板。

## 1. 背景与问题

v0.2 跑通了「反查流量词 → 过滤 → 分层 → 写」，但有四个缺口：

1. **规则过时**：2026-07-27 起非媒体类标题 ≤75 字符（Seller Central 官方公告，已核实）。参考运行的标题超过 150 字符。
2. **卖点没有来源**：卖点全从 S1 需求点反推，规格只能写〔待填〕。卖家自己的产品信息进不来。
3. **买家声音没用上**：S1 缓存了 39 条竞品差评原文，S3 只用了一句话摘要；没有 Rufus 买家问题。
4. **靠模型自己数字符**：长度、字节、重复词、违禁词没有确定性检查。

## 2. 目标与非目标

**目标**
- 输出一版可直接交给运营审的美国站 Listing：标题、Item Highlights、五点、长描述、后台搜索词。
- 每个关键词有来源和数字；每个买家关心点有对应的文案位置。
- 硬规则由脚本检查，不靠模型自觉。
- 卖家精灵调用 ≤5 次（流量词 1、对标详情 1–2、好评 1、补查 0–1）；重跑读缓存为 0 次。

**非目标**
- 不写附图策划、A+、多站点多语言。
- 不读产品图片（SPEC 不做图片；也保证 Codex 能复跑）。
- 不上传 Seller Central，不生成上架模板表。
- 不照搬老陈 skill 的规则原文（无开源协议），只借思路。

| P0 | F2 买家关心点 | 从差评、好评（和 Rufus 问题，如有）归纳关心点 | 每个关心点带出现次数 + 1 句原话；≥3 个 |
| P0 | F2b 对标 Listing 拆解 | 读对标竞品的标题、五点、属性表：标题结构、五点主题顺序、覆盖了哪些词、写了哪些规格、哪些关心点**没回应**（结合 F2）、有哪些违规写法（如 #1） | 输出拆解表；只借结构和缺口，不复述原句 |
| P0 | F3 取词 + 清洗打标 | `traffic_keyword` 反查；去重、剔除品牌 / IP / 不相关词；打 high / relevant | 剔除词有原因；缓存命中不重复调用 |
| P0 | F4 分层埋词 | 标题 2–3 词 / Highlights 2–4 / 五点 5–8 / 长描述 3–6 / 后台填满字节 | 每个词只放一层，低层不重复高层 |
| P0 | F5 写文案 | 模型写 `s3_draft.json` | 字段齐全；无来源规格为〔待填〕 |
| P0 | F6 检查 + 渲染 | `check_listing.py` 检查 draft，通过后渲染 `s3_listing.md` | 见下方规则表；最多修 2 轮，仍不过如实标「未通过」 |
| P2 | F7 Rufus 浏览器采集 | 用标题核心词在 amazon.com 问 Rufus，取推荐问题 | 成功写 `raw/rufus_<词>.json`（status=completed）；任何失败写 status=skipped + 原因，流程继续 |

### 文案规则（F5 写、F6 查）

| 字段 | 规则 | 上限 | 核实 |
|---|---|---|---|
| 标题 | `[Brand]` + 核心品名 + 1–2 差异点 + 〔待填：尺寸 / 件数〕；核心词在前 40 字符 | 75 字符含空格，按品牌名 10 字符预留；禁用 `! $ ? _ { } ^ ¬ ¦`；同词 ≤2 次（介词冠词连词除外） | 已核实 |
| Item Highlights | 标题放不下的材质、场景、规格；一行短语；不重复标题 | 125 字符 | 已核实 |
| 五点 | 5 条，大写短语开头；1–3 回应最高频关心点，4 材质，5 更多用途 | 每条 ≤255 字符（保守） | 未核实 |
| 长描述 | 场景开头，2–3 个使用场景，陈述句 + 具体数字，纯文本 | ≤2000 字符 | 未核实 |
| 后台搜索词 | 小写、空格分隔、无标点、无品牌词、无停用词、不重复前台 | ≤249 字节 | 仅第三方 |
| 全字段 | 无竞品品牌名、无 IP 词；无 best / #1 / guaranteed / free shipping 等 | — | 行业共识 |
| 全字段 | 不抄对标文案：和对标五点任意连续 8 个词相同即判不通过 | 脚本检查 | 本项目自定 |

### 输出 `s3_listing.md`

1. 文件头（按 contracts）
2. 针对候选
3. 买家关心点 → 卖点对照（关心点 / 次数 / 原话 / 对标回应了没 / 我们回应位置）
3b. 对标 Listing 拆解（标题结构、五点主题、写到的规格、缺口）
4. 标题、Item Highlights、五点、长描述、后台搜索词
5. **关键词清单**：词 / 放在哪（标题、Highlights、五点、长描述、后台）/ 来源和数字
6. 有意没用的词及原因
7. Rufus 问题覆盖清单（status=skipped 时写「本次跳过：原因」，不伪造）
8. 上架前待确认清单（全部〔待填〕项）
9. 检查结果
10. 卖家精灵调用次数

中间产物：`runs/<本次>/s3_draft.json`（不入库，runs 里的参考运行除外）。

- 不编数据、不写竞品品牌、不提交 key 和真实店铺数据。
- 只改 `stages/s3-listing/`、`samples/s3_listing.md`；`SKILL.md`、`contracts/`、`SPEC.md` 的改动走第 7 节。
