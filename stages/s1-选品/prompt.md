# S1 选品（有趋势、可以选的品）

> 负责人：组长兜底（Dylan）　·　v1.0（2026-09-13）
> 方法参考开源 [bulus-amazon-skill](https://github.com/buluslan/bulus-amazon-skill)（MIT）的场景 02 趋势验证、03 细分机会挖掘、04 竞品地图、12 评论复盘，按本项目的交接约定和卖家精灵实测结果改写。
> 输出字段的最低要求见 `contracts/交接内容.md` 的「S1 选品」。参考产出：`runs/2026-09-12_bamboo-drawer-organizer/s1_选品.md`。

## 目标

种子词 → **在涨、且真能出单的词** → 这些词下**值得对标的竞品** → 从竞品差评里找出**没被满足的需求**。
不追求把市场讲全，只要给下游 3 个有依据、互相独立的候选。

## 输入

| 参数 | 必填 | 说明 |
|---|---|---|
| 种子词 | 是 | 英文。品牌词、IP 词直接拒绝，请用户换词 |
| 站点 | 否 | 默认 `US` |
| 视角 | 否 | `铺货` / `精品`，影响第 5 步挑候选；不填按「通用」 |

所有卖家精灵原始返回存 `runs/<本次>/raw/<工具名>_<参数>.json`，**调用前先看缓存**。

## 步骤

### 1. 找词（1 次）

`keyword_research`：`{"request":{"marketplace":站点,"keywords":种子词,"order":{"field":"searches","desc":true},"size":20}}`

取每个词的：`searches`（月搜索量）、`purchases`（月购买量）、`purchaseRate`、`searchMonthlyCr`（月环比 %）、`searchNearlyCr`（近 3 个月增长 %）、`products`、`supplyDemandRatio`、`avgPrice`、`month`。

> ⚠️ **不要用 `aba_research_weekly` 的 `includeKeywords` 找词**：2026-09-12 实测没有过滤作用，返回的是全站热词（labor day sale 之类），白扣 1 次。

### 2. 筛词、分档（0–1 次）

先剔除，剔除的写原因：
- 品牌词（含竞品品牌名，如 `pipishell ...`）、IP 词
- 月购买量 < 100 的词：有搜索没订单

可选 1 次：对剩下购买量前 8 的词调 `keyword_miner`（`keywordList` 批量），拿 `monopolyClickRate`（点击集中度）和 `bid`。**这份缓存 S4 查竞价时能直接复用。**

分四档（开源场景 03 的思路）：

| 档 | 条件（阈值可改） |
|---|---|
| 优先研究 | 近 3 个月增长 > 0 或月环比 > 20%，且购买量 ≥ 300 |
| 可切入需验证 | 增长为正但购买量 100–300，或购买量高但增长持平 |
| 仅曝光机会 | 点击集中度 > 0.5（头部锁死点击）；没查集中度就不用这一档 |
| 暂不投入 | 近 3 个月增长 < -10% |

### 3. 趋势验证（≤3 次）

「优先研究」里挑 3 个词，各调一次 `aba_research_trend`：`{"marketplace":站点,"keyword":词,"timeGranularity":"M"}`。只看最近 14 个月。

每个词判断（开源场景 02 的思路），**不预设涨跌，先看数据**：
- **方向**：最近 4 个月走势 + 与去年同月对比。
- **排除假象**：
  - 在涨 → 只是回到去年同期水平的，算**季节性回升**，不算增长
  - 在涨 → 购买量没跟着涨（第 1 步的 `purchases` 很低），标**可能是虚火**
  - 在跌 → 去年同期也跌，算**季节性回落**
- **结论**：`上升期` / `成熟期` / `季节性` / `衰退` 四选一，写一句依据，数字要带月份。

在涨词表只放结论为「上升期」或「成熟期」的词，至少 3 个；不够就把「季节性」的补进来并注明。

### 4. 竞品地图（1–2 次）

`product_research`：`{"request":{"marketplace":站点,"keyword":最精准的在涨词,"matchType":1,"variation":"Y","order":{"field":"total_units","desc":true},"size":20}}`

> `matchType: 1` 是词组匹配。默认的模糊匹配容易混进不相关的品。

取每个 ASIN 的：`units`（月销）、`unitsGr`（销量增长 %）、`price`、`availableDate`（毫秒时间戳，要换成年月）、`ratings`、`ratingsCv`、`brand`、`sellerNation`、`fba`、`profit`、`parent`。

分三层（开源场景 04 的思路），每层写划分依据：
- **垄断层**：评分数 > 20,000，或月销前 3 且品牌出现多个 ASIN。默认避开。
- **腰部层**：评分数 500–20,000 且销量增长 > 0。可以对标。
- **新冒头**：上架 ≤ 18 个月且月销 > 1,000。说明新品能跑出来。

另外补一句**价格带**：成交最集中的价格区间，按月销加总。

### 5. 挑 3 个候选（0 次）

从腰部层和新冒头里挑，规则：
- **互相独立**：不同品牌、不同父体（`parent` 不同），**不能 3 个都是同一家的变体**。
- **尽量覆盖不同的在涨词**，每个候选都要能追到一个在涨词。
- 视角：
  - `铺货`：优先新冒头、评分数少但销量涨得快的
  - `精品`：优先差评多、有明确改良空间的
  - `通用`：两类各至少 1 个
- 每个候选写一句「为什么选它」。

### 6. 需求点（≤3 次）

每个候选调一次 `review`：`{"marketplace":站点,"asin":ASIN,"starList":[1,2,3],"size":20}`。

按开源场景 12 把差评归因，每条差评归一类：
- **产品缺陷**（开胶、断裂、异味）→ 改良信号
- **预期落差**（比想象小、放不下）→ 文案和规格要写清楚
- **物流**、**使用门槛** → 记一笔，一般不当需求点

**需求点** = 该候选出现次数最多的「产品缺陷」或「预期落差」。写成：一句话 + 次数和分母（如「差评 9/20」）+ 1 句买家原话。
差评少于 5 条的，注明「样本少」。

### 7. 写 `s1_选品.md`

按 `contracts/交接内容.md` 写 ① 在涨词表、② 候选竞品表，再附：
- 词分档表（第 2 步）
- 竞品分层（第 4 步，每层列 ASIN、品牌、月销、价格）和价格带
- 候选理由（第 5 步）
- **跨候选的共同需求**：一两句话，给 S3 写卖点用

写完自检：
- [ ] 在涨词 ≥ 3 个，每个有数字、方向和月份
- [ ] 候选 3 个，品牌和父体都不重复，每个都能追到在涨词
- [ ] 每个需求点有次数、分母和原话
- [ ] 所有数字都标了来源工具
- [ ] 文件头和末尾调用次数齐全

## 额度

本阶段 ≤10 次：keyword_research 1、keyword_miner 0–1、aba_research_trend 3、product_research 1–2、review 3。
