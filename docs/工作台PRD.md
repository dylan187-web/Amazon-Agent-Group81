# PRD · Amazon Agent 工作台（演示用可视化界面）

> 本文件是讨论和执行之间的契约。执行的工具（Claude Code / Codex）只认这份文件，不认对话。

## 1. 背景与问题

四个阶段（S1 选品 → S2 利润 → S3 Listing → S4 广告）已经真实跑通，全链路测试全部通过。但产出是散在 `runs/<本次>/` 里的 Markdown、JSON 和图片：
- **评审看不出链路**：录屏只能翻文件，看不出「一个词怎么一路追到广告方案」。
- **和封面对不上**：封面画的是一个带左侧导航和四步卡片的工作台，实际没有这个界面。

官方评选标准要求作品「可展示、可体验」。演示视频不超过 5 分钟，工作台就是视频的主画面。

## 2. 目标与非目标

**目标**
- 打开一个网页，就能按封面的样子逐步回放一次真实运行：输入种子词 → 四步依次亮起 → 点进每一步看结论。
- 页面上每个数字都来自 `runs/` 里的真实产出，不写死、不编。
- 换一次运行只需重跑一条命令，页面自动更新。
- 5 分钟内能讲完一条完整追踪：在涨词 → 候选 C2 → 每件剩 $19.30 → Listing 标题和图 → 14 个投放词。

**非目标**
- **不在网页里真的调用卖家精灵或大模型**：没有后端，也不保存 key。真实运行仍在 Claude Code / Codex 里完成，工作台只负责展示。
- 不做登录、多用户、数据库。
- 不做「数据看板」这类封面上有、但我们没有数据的页面。封面上的「数据看板」菜单可以隐藏，或者显示「规划中」。
- 不做移动端精修，只保证桌面 1920×1080 录屏清楚。

## 3. 用户与场景

- **主要场景**：组长在电脑上打开工作台录屏，按「首页 → 选品 → 利润 → Listing → 广告」讲一遍。
- **次要场景**：评审或开源用户 clone 仓库后，双击打开页面，直接看到参考运行的结果。

## 4. 功能清单

| 优先级 | 功能 | 说明 | 验收标准 |
|---|---|---|---|
| P0 | 数据打包脚本 | `workbench/build.py runs/<本次>` 读取 s1–s4 的 md、`s4_draft.json`、`s3_draft.json`、图片清单，输出 `workbench/data.js`。用 JS 文件而不是 JSON，是因为浏览器用 `file://` 打开时不能 fetch | 对参考运行执行一次，生成 data.js 且无报错；改一个上游数字重跑，页面跟着变 |
| P0 | 首页 | 视觉照封面：左侧导航加主区。输入框预填「对 bamboo drawer organizer 跑一遍」，点箭头后四张步骤卡依次亮起（回放动画，每步约 1 秒），每张卡显示一个关键数字 | 四张卡片的数字分别是：3 个在涨词 / 选中 C2 · 每件剩 $19.30 / 标题 + 检查全过 / 14 个投放词。都从 data.js 读取 |

| P0 | Listing 生成页 | 标题、Highlights、五点、后台词；买家关心点表；检查结果徽章（全部通过）；S3 图片缩略图 | 和 `s3_listing.md` 一致；图片能显示 |

| P1 | 链路追踪高亮 | 在任一页点一个词或候选，其他页里同一个词或候选一起高亮，比如 `expandable bamboo drawer organizer` 从 S1 一路追到 S4 | 至少能追踪 1 个词、1 个候选 |
| P1 | 来源悬停 | 鼠标悬停在数字上，显示来源工具和统计周期 | 在涨词和竞价两处可用 |
| P1 | 底部调用统计 | 显示本次卖家精灵总调用次数，按阶段拆分 | 数字与各文件末尾一致 |
| P2 | 「真实运行」说明页 | 展示在 Claude Code / Codex 里怎么一句话触发，附终端录屏或截图 | — |

## 5. 约束与红线

- **技术**：单个 `workbench/index.html` 加 `data.js` 加 `build.py`。只用浏览器原生能力，外部库最多引一个 CDN 图表库，也可以不用。Python 只用标准库。
- **诚实**：页面上不出现产出文件里没有的数字；缺的写「未查到」；估算口径必须和数字一起显示。
- **公开仓库**：不放 key、不放真实店铺数据；图片沿用 S3 已生成的概念图。
- **协作**：工作台放在 `workbench/`，不改 `stages/` 和 `runs/` 里的已有文件。
